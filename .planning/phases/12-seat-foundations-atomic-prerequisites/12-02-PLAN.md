<objective>
Convert the `done` and `tip` routes from whole-session GET -> spread -> SET in JavaScript to field-level atomic Lua scripts, keeping their HTTP contract byte-for-byte compatible with v2.0 clients.

Purpose: v2.1 makes `people[]` the hottest-changing field (every friend claims a seat right after the link is shared). The current done/tip routes rewrite the entire session and can silently revert a concurrent person-list change (PITFALLS Pitfall 4). This must land before seat claiming (Phase 13). ROADMAP Phase 12 success criterion 3.

Harness decision (justified): this plan does NOT introduce the real-Redis Lua harness. redis-server is not installed on this machine, the harness design is the flagged research item of Phase 13, and Phase 13 success criterion 2 explicitly re-verifies done and tip under simultaneous use against real Redis (REL-01/REL-03). To make that zero-refactor, the scripts move into an importable module (lib/sessionLua.ts) instead of staying route-local (Next.js route files may only export route fields). Phase 12 proves the clobber window is gone structurally: mocked route tests assert redis.get/redis.set are never called and exactly one redis.eval runs, and static script tests assert each script writes only its own field.

Output: lib/sessionLua.ts, rewritten done/tip routes, updated route tests, static Lua tests.
</objective>

Proven Lua pattern (app/api/session/[sessionId]/edit/route.ts UPDATE_CURRENCY_SCRIPT / RENAME_PERSON_SCRIPT):
  local raw = redis.call('GET', KEYS[1]); if not raw -> return 'session_not_found'
  local ok, session = pcall(cjson.decode, raw); if not ok -> return 'invalid_session'
  mutate one field; redis.call('SET', KEYS[1], cjson.encode(session), 'EX', 86400); return 'OK'
  Person lookup: for _, p in ipairs(session.people) do if p.id == personId ... end
  TS side: const result = await redis.eval(SCRIPT, [`session:${sessionId}`], [arg1, arg2]); map string result -> HTTP status
  NOTE: redis.multi() is NOT atomic on Upstash REST — Lua eval is required.

Current done route contract (app/api/session/[sessionId]/done/route.ts):
  body { personId: non-empty string, done: boolean }
  400 'Invalid JSON body' | 400 'Invalid personId' | 400 'Invalid done: must be boolean'
  404 { error: 'session_not_found' }
  400 { error: 'Invalid personId: not in session' }
  200 { ok: true }; sets claims.donePeople[personId] = done (true OR false — false is stored, not deleted; D-08)
  500 { error: 'Done failed' }

Current tip route contract (app/api/session/[sessionId]/tip/route.ts):

  404 { error: 'session_not_found' }; 400 { error: 'Invalid personId: not in session' }
  200 { ok: true }; sets tips[personId] = tipCents
  500 { error: 'Tip failed' }
