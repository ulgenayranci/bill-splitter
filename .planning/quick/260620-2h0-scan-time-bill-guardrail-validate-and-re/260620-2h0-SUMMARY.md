# Quick Task 260620-2h0: Scan-Time Bill Guardrail Summary

Adds a pure scan-time reconciliation layer that converts raw OCR figures into canonical integer-cent LINE TOTALS before anyone claims, fixing systematic undercharging on multi-quantity lines ("Tuborg ×2 @ 450" now splits as 900, not 450), trusting the printed line total on conflict, and surfacing a non-blocking "possible missing items" warning when the printed subtotal disagrees with the reconciled sum.

## What Was Built

1. **`Item.unitPriceCents`** (optional, integer cents) on the Zustand store. `addItem`/`updateItem` now treat their `priceCents` arg as the canonical LINE TOTAL and derive `unitPriceCents = round(priceCents / quantity)` via the exported `deriveUnitPriceCents` helper. The field flows through `SessionPayload.items` automatically (sessionSchema imports the shared `Item` type — no enumeration to patch). `billMath` is untouched.

2. **`lib/reconcileScannedBill.ts`** — a pure function (no React/store imports) with exported types (`ReconcileInputLine`, `ReconciledItem`, `ReconcileResult`) and a `TOLERANCE_CENTS = 2` constant. Per-line derivation: both-match → accept; both-conflict → trust printed total + flag `corrected`; unit-only → extend by qty; total-only → derive unit; neither → defensive legacy-as-line-total with qty coerced to 1. Bill-level completeness compares an optional printed subtotal against the reconciled sum. Integer-cents only; `Math.round` applied solely to integer-cents division.

3. **Expanded OCR contract** (`app/api/ocr/route.ts`) — prompt + strict json_schema now return per line `unitPriceCents`/`lineTotalCents` (nullable via `["integer","null"]` unions, all props in `required`) and a top-level nullable `subtotalCents`. Server filter coerces non-positive-integers to null and drops a line only when both prices are null. Returns `{ items, currencyCode, subtotalCents }`. Currency normalization, auth, and `maxDuration` preserved.

4. **Scan-flow wiring** (`components/wizard/SetupStep.tsx`) — after OCR, `reconcileScannedBill(ocrItems, { subtotalCents })` runs before expand. The reconciled LINE-TOTAL `priceCents` is sent to `/api/expand`; `unitPriceCents`/`quantity` are re-attached by index after expand returns (expand drops `unitPriceCents`). The expand-failure fallback builds items from the reconciled lines. A non-blocking guardrail renders near the scan tile: an informational corrected-count note and a prominent (but non-blocking) `role="alert"` completeness warning. `canContinue` gating is unchanged; guardrail clears on retake/error.

5. **Multi-qty card display** (`components/split/ClaimableItemCard.tsx`) — qty>1 items show `"<unit> each · <lineTotal> total"` using `item.unitPriceCents ?? round(item.priceCents / quantity)` (legacy fallback). Splitting still uses `item.priceCents` via `computeQtyWeightedShares` — unchanged.
