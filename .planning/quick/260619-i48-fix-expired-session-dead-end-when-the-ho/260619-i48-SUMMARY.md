# Quick Task 260619-i48: Fix Expired-Session Dead-End Summary

Hosts whose persisted bill points at an expired Redis session can now escape the dead-end via a "Start over" button that clears the stale store and returns them to a fresh homepage; guests opening an expired shared link still see the unchanged expired message with no redirect.

## What Changed

### Task 1 — Optional `onStartOver` on `SessionExpiredScreen` (commit df97d15)
- Added optional `onStartOver?: () => void` prop.
- When provided, renders a "Start over" `Button` (from `@/components/ui/button`) below the existing paragraph.
- When absent (guest case), markup is byte-identical to before: same `role="alert"`, same `Link2Off` icon, same heading "This session has expired", same paragraph text.

### Task 2 — Host-vs-guest branch on `SessionNotFoundError` (commit b45ea0f)
- Added value import of `useBillStore` and `useRouter` from `next/navigation`; instantiated `const router = useRouter()`.
- `isOwnExpiredBill = useBillStore.getState().sessionId === sessionId` — imperative read (no hook), safe with the `skipHydration` store.
- `handleStartOver()`: calls `useBillStore.getState().reset()` (sessionId → null), removes `split:{sessionId}:personId` inside the existing localStorage try/catch idiom, then `router.replace('/')`.
- Error branch now: host (`isOwnExpiredBill`) → `<SessionExpiredScreen onStartOver={handleStartOver} />`; guest → `<SessionExpiredScreen />` unchanged. No render-phase redirect.
- No other logic touched; the `if (!session) … Loading…` line remains directly after the error branch.
