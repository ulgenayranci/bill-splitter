<objective>
Fix the expired-session dead-end loop. When the homepage's resume-redirect sends a host to a saved `/split/{sessionId}` whose server session has expired in Redis, the host is currently stranded on `SessionExpiredScreen` forever — every visit to `/` bounces them straight back to the dead link because their `useBillStore.sessionId` still holds the dead id.

The fix: when `/split/{sessionId}` is detected as not-found AND the locally persisted `useBillStore` sessionId matches the expired sessionId (this is the host's OWN stale bill driving the redirect), clear the stale persisted bill via `reset()` and send the user to the fresh homepage (`/`). For guests (no matching persisted sessionId) the existing `SessionExpiredScreen` message is correct and must be preserved unchanged — no redirect.

Purpose: Hosts can recover after their 24h session TTL expires instead of being permanently locked out of the app.
Output: Conditional host-vs-guest handling on `SessionNotFoundError`; an optional "Start over" action on `SessionExpiredScreen`.
</objective>
